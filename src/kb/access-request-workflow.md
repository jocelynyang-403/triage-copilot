# Standard Access Request Workflow

This runbook defines how employees, contractors, and vendors request access to Meridian Cloud, Inc. systems. IT / Access owns provisioning, deprovisioning, and the access review calendar.

## How to Submit

All access requests are filed through the IT / Access service portal at help.meridiancloud.com. A valid request must name the target system or resource, the specific role or permission level needed, a business justification, and the requester's manager. Requests missing any of these fields are returned rather than guessed at, because incomplete justifications are the leading cause of over-provisioning.

## Approval Chain

Standard, role-appropriate access (for example, a new hire needing read access to a team dashboard) requires only the requester's manager to approve. IT / Access provisions these within one business day of approval. Elevated or sensitive access — production databases, admin consoles, financial systems, or anything granting write access to customer data — requires both manager approval and resource-owner approval, and is provisioned within two business days. Production database changes additionally require a linked change ticket.

## Information Required

For every grant, IT / Access records who approved it, the justification, and an expiration or review date. Standing access is reviewed quarterly; access granted for a specific project is set to expire when the project closes.

## Contractor and Vendor Access

External access differs from employee access in three ways. First, every contractor or vendor must have a named internal sponsor who is accountable for the account. Second, access is time-boxed to a maximum of 90 days and auto-expires on the end date, with renewal requiring a fresh request. Third, contractors receive least-privilege access scoped to the single engagement — never broad or standing roles. Offboarding is triggered automatically at expiry, and the sponsor is notified three days beforehand.

## Urgent Requests

Access blocking active work (for example, a locked-out account during business hours) is treated as priority and worked ahead of the standard queue.

## Ownership

IT / Access owns all provisioning decisions and the audit trail.
